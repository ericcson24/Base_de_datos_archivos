21) Root cause and permanent fix (no watchdog)
- Symptom:
  - "Everything drops together" every so often.
- Evidence captured from Docker daemon journal:
  - Multiple containers receive "stopping restart-manager" at the same time.
  - Then daemon logs: "Daemon shutdown complete".
  - Shortly after, docker.service starts again and restores containers.
- Conclusion:
  - This is not an app-level crash loop.
  - The whole Docker daemon inside WSL was being stopped/restarted at host/WSL
    lifecycle level, which drops all services together.
- Permanent fix applied:
  - Created host file C:/Users/Administrador/.wslconfig with:
    - [wsl2]
    - vmIdleTimeout=0
  - Applied with one-time command:
    - wsl --shutdown
- Why this fix:
  - Prevents WSL2 VM idle shutdown from stopping dockerd.
  - Keeps stack continuity without using watchdog scripts.
- Validation after fix:
  - Docker service in WSL reached active state.
  - All compose services restored and running.
  - http://localhost:8080 -> 200
  - https://proyectonube.xyz -> 200

22) Follow-up stability fix (WSL shutdown loop on this host)
- New evidence observed:
  - Ubuntu/WSL was entering full shutdown.target repeatedly.
  - Pattern in journal:
    - Started docker.service
    - Stopping docker.service
    - Daemon shutdown complete
    - Full WSL unmount/shutdown sequence
  - This occurred every ~1 minute and caused recurrent Cloudflare 502 windows.
- Important correction:
  - vmIdleTimeout value in .wslconfig did not stop the shutdown loop on this
    specific host/build behavior.
- Stabilization applied:
  - Created Windows Scheduled Task:
    - TaskName: WSL-Ubuntu-Anchor
    - Trigger: At logon (Administrador)
    - Action: wsl.exe -d Ubuntu -- sh -lc "while true; do sleep 600; done"
  - Started task immediately and kept stack up with docker compose up -d.
- Why this works:
  - Keeps one lightweight WSL process alive so the distro is not auto-terminated.
  - Does not restart containers; it only prevents host-side WSL shutdown.
- Validation after applying anchor:
  - http://localhost:8080 -> 200
  - https://proyectonube.xyz -> 200
  - No new docker shutdown events after last start in the verification window.

24) Definitive 502 fix (Cloudflare Host Error while local=200)
- Incident pattern:
  - Local gateway stayed at 200, but Cloudflare intermittently returned 502.
  - Tunnel was connected, yet some requests did not reach gateway logs.
- Root cause found:
  - The `tunnel` service had external DNS override (`1.1.1.1`, `8.8.8.8`).
  - Cloudflared ingress target is `http://gateway:80` (Docker internal name).
  - With external DNS forced, internal service-name resolution can fail,
    producing Cloudflare 502 Host Error.
- Fix applied in docker-compose.yml:
  - Removed `dns:` override from `tunnel` service.
  - Kept `--protocol http2` for cloudflared (QUIC had handshake timeouts on
    this network).
  - Kept tunnel decoupled from gateway startup (`depends_on` removed earlier).
- Validation after fix:
  - Tunnel registered 4 active connections (connIndex 0..3).
  - LOCAL=200 on http://localhost:8080
  - CF=200 on https://proyectonube.xyz
